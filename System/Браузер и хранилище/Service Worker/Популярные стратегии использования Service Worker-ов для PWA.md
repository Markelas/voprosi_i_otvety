## 1. Cache First (Кэш прежде всего)

**📖 Что это такое**
Service Worker сначала проверяет наличие файла в кэше. Если найден — отдаёт мгновенно. Если нет — идёт в сеть, скачивает и сохраняет для будущих визитов.

**🎯 Для чего применяется**
Для статичных ресурсов, которые редко меняются: CSS, JavaScript-библиотеки, шрифты, логотипы, иконки.

**💻 Короткий пример**
```javascript
self.addEventListener('fetch', event => {
  event.respondWith(
    caches.open('static-v1').then(cache => {
      return cache.match(event.request).then(cached => {
        return cached || fetch(event.request).then(response => {
          cache.put(event.request, response.clone());
          return response;
        });
      });
    })
  );
});
```

**➕ Плюсы**
- Мгновенная скорость (ответ за 0–5 мс). Пользователь не ждет загрузки при повторных визитах.
- Экономия трафика и ресурсов сервера - файлы скачиваются один раз
- Идеально для тяжёлых SPA-бандлов 

**➖ Минусы**
- Проблемы с обновлениями — пользователь может видеть старую версию
- **Решение**: добавлять хеш в имя файла (например, `app.a7f8g9.js`). При каждом релизе хеш меняется, и Service Worker считает это новым файлом.

## 2. Stale-While-Revalidate (Сначала кэш, фоном обновляем)

**📖 Что это такое**
Самая «умная» и популярная стратегия. Service Worker мгновенно отдает пользователю данные из кэша (если они там есть), но в фоне (не блокируя интерфейс) отправляет запрос в сеть, скачивает свежую версию и обновляет кэш для следующего визита. Пользователь не ждет. 

**🎯 Для чего применяется**
Для данных, где скорость критична, но и свежесть хоть немного, но важна:  
Аватарки пользователей, названия товаров в каталоге, статьи в блоге, курсы валют (с допустимой погрешностью в 1–2 минуты), погода.

**💻 Короткий пример**
```javascript
self.addEventListener('fetch', event => {
  event.respondWith(
    caches.open('dynamic-v1').then(cache => {
      return cache.match(event.request).then(cached => {
        const fetchPromise = fetch(event.request).then(response => {
          cache.put(event.request, response.clone());
          return response;
        });
        return cached || fetchPromise;
      });
    })
  );
});
```

**➕ Плюсы**
- **Идеальный баланс**. Вы получаете скорость кэша и актуальность сети одновременно.
- Пользователь **никогда не видит белый экран** и не ждет загрузки — контент появляется моментально.
- Отлично подходит для мобильного интернета с нестабильной скоростью.

**➖ Минусы**
- **Эффект «призрачных данных»**. В течение 1–5 секунд (пока идет фоновая загрузка) пользователь видит старую информацию. Для чатов, биржевых котировок или остатков на складе это может ввести в заблуждение.
- **Увеличение трафика** — каждый раз, даже при наличии кэша, происходит фоновый запрос в сеть (хотя это и экономит время пользователя).

## 3. Network First (Сеть прежде всего)

**📖 Что это такое**
Сначала всегда делается «живой» запрос на сервер. Если сервер ответил — данные отдаются пользователю, а копия сохраняется в кэш. Если сервер недоступен (офлайн, 500-я ошибка, таймаут) — тогда в дело вступает последняя сохраненная версия из кэша.

**🎯 Для чего применяется**
Для критически важных и динамичных данных, где цена ошибки (устаревших данных) очень высока, например, баланс банковского счета, статус оплаты заказа, персональные уведомления, подтверждение бронирования, корзина интернет-магазина.

**💻 Короткий пример**
```javascript
self.addEventListener('fetch', event => {
  event.respondWith(
    caches.open('critical-v1').then(cache => {
      return fetch(event.request)
        .then(response => {
          cache.put(event.request, response.clone());
          return response;
        })
        .catch(() => cache.match(event.request));
    })
  );
});
```

**➕ Плюсы**
- **Гарантированная актуальность** (100% свежие данные, пока есть интернет).
- Пользователь видит реальную картину мира, а не «вчерашний день».
- При потере сети приложение не падает, а переключается на офлайн-режим с последними данными.

**➖ Минусы**
- **Самая медленная стратегия**. Пользователь всегда ждет ответа от сервера (даже если кэш супер-быстрый). Если сервер тормозит (latency 400 мс) — пользователь чувствует это как «тормоза» приложения.
- **Сильная зависимость от бэкенда**. Если ваш API упал, но интернет у пользователя есть — он увидит ошибку, хотя мог бы видеть старый кэш (пока бэкенд чинят).

## 4. Pre-caching (Предзагрузка при установке)

**📖 Что это такое**
Это не столько стратегия ответа на запрос, сколько процесс установки. Когда пользователь впервые заходит на сайт, Service Worker в фоне (во время события `install`) скачивает и сохраняет в кэш строго определенный набор файлов — «скелет» приложения.

**🎯 Для чего применяется**
Для создания **App Shell** — минимального каркаса приложения:  
Главный `index.html`, корневые CSS, ядро JavaScript (`app.js`), манифест (`manifest.json`), стартовая картинка. Эти файлы нужны для того, чтобы приложение запустилось вообще без сети.

**💻 Короткий пример**
```javascript
const CACHE_NAME = 'app-shell-v1';
const PRECACHED = [
  '/',
  '/index.html',
  '/style.css',
  '/app.js',
  '/manifest.json'
];

self.addEventListener('install', event => {
  event.waitUntil(
    caches.open(CACHE_NAME)
      .then(cache => cache.addAll(PRECACHED))
      .then(() => self.skipWaiting())
  );
});

self.addEventListener('fetch', event => {
  event.respondWith(
    caches.match(event.request)
      .then(cached => cached || fetch(event.request))
  );
});
```

**➕ Плюсы**
- **Гарантированный офлайн-запуск**. Если пользователь зашел на сайт хотя бы раз, он сможет открыть его в самолете или метро.
- **Мгновенный старт** при повторных визитах — все критичное уже лежит в телефоне.

**➖ Минусы**
- **Тяжелый первый визит**. Если положить в прекэш 10 МБ файлов — пользователь на медленном 3G будет ждать 30 секунд и, скорее всего, закроет вкладку.
- **Правило**: В прекэш кладем **только самое необходимое** (до 300–500 КБ). Всё остальное (тяжелые картинки, видео) подгружается лениво (lazy loading) другими стратегиями.

## 5. Background Sync (Фоновая синхронизация)

**📖 Что это такое**
Продвинутая техника. Если пользователь отправил данные (форму, сообщение, заказ), а интернет пропал, Service Worker ловит это, сохраняет запрос в специальную очередь (IndexedDB) и, как только сеть появляется, автоматически повторяет отправку в фоне, даже если вкладка с приложением уже закрыта.

**🎯 Для чего применяется**
Для действий, которые нельзя потерять: отправка форм, сообщений, комментариев, оформление заказов.

**💻 Короткий пример**
```javascript
// Регистрируем синхронизацию на клиенте
navigator.serviceWorker.ready.then(sw => {
  sw.sync.register('sync-messages');
});

// В Service Worker обрабатываем событие
self.addEventListener('sync', event => {
  if (event.tag === 'sync-messages') {
    event.waitUntil(
      getPendingMessages().then(messages => {
        return Promise.all(messages.map(msg => 
          fetch('/api/messages', { method: 'POST', body: msg })
        ));
      })
    );
  }
});
```

**➕ Плюсы**
- Пользователь может работать офлайн без потери данных
- Автоматическая отправка при появлении сети
- Работает даже при закрытом приложении

**➖ Минусы**
- Сложность реализации (нужно хранить очередь в IndexedDB)
- Риск конфликтов (например, если товар уже купил другой пользователь)

## 6. Предзагрузка (Prefetching)

**📖 Что это такое**
Предугадываем действия пользователя и заранее подгружаем ресурсы следующей страницы. Например, когда пользователь наводит курсор на ссылку.

**🎯 Для чего применяется**
Для создания мгновенной навигации между страницами (как в нативных приложениях).

**💻 Короткий пример**
```javascript
// На странице — при наведении на ссылку
document.querySelector('a.next-page').addEventListener('mouseenter', () => {
  navigator.serviceWorker.controller?.postMessage({
    type: 'PREFETCH',
    url: '/next-page'
  });
});

// В Service Worker
self.addEventListener('message', event => {
  if (event.data.type === 'PREFETCH') {
    event.waitUntil(
      caches.open('prefetch-v1').then(cache => {
        return cache.add(event.data.url);
      })
    );
  }
});
```

**➕ Плюсы**
- Навигация становится мгновенной
- Отличный пользовательский опыт

**➖ Минусы**
- Пожирает трафик пользователя
- Может разряжать батарею на мобильных устройствах
- Нужно аккуратно выбирать, что предзагружать

## 🎯 Главный принцип

> **Никогда не используйте одну стратегию для всего приложения.**

В реальном проекте вы комбинируете все подходы:
- **Pre-caching** для App Shell
- **Cache First** для JS/CSS с хешами
- **Stale-While-Revalidate** для картинок и списков
- **Network First** только для критических API
- **Background Sync** для форм и комментариев
- И всегда добавляете fallback — красивый экран «Нет соединения»
